# TIL — 프로젝트 중 학습 기록

> 프로젝트 투입 이후, 주 1회 고정 주기 대신 **그때그때 부딪힌 주제 하나**를 같은 깊이로 정리한다.
> 형식은 기존 주간 테크리뷰와 동일하다. "짧게 메모"가 아니라 **읽으면 그 주제가 이해되는 글**을 목표로 한다.

---

## 파일 규칙

- 경로: `til/YYYY_MM_DD_주제.md`
- 제목: `# YYYY-MM-DD. 주제 — 한 줄 요약`
- 각 글은 **독립적으로 완결**되어야 한다. "지난번에 다룬 ~", "다음에 볼 ~" 같은 **글 사이의 시간적 참조를 쓰지 않는다.** 필요한 선행 개념은 그 글 안에서 다시 설명한다.

## 글 구성

1. **도입** — 현장에서 마주친 문제 제기. "왜 이걸 알아야 하나"부터.
2. **개념 뜯어보기** — 표면 기능이 아니라 **왜 그렇게 설계됐는지**까지. 표·ASCII 다이어그램·코드 예시 적극 활용.
3. **핵심 통찰 박스** — 글당 3~5개. 인용 블록으로:
   ```
   > **핵심 통찰 — "한 문장으로 압축한 주장"**
   >
   > 왜 그런지, 실무에 뭘 바꾸는지.
   ```
4. **정리 & SI 관점의 시사점** — 요약 불릿 + 우리 SI 프로젝트에 주는 함의(토론 포인트) + 마지막에 **토론거리** 블록.
5. **더 살펴볼 자료** — 공식 문서 우선, 각 링크에 한 줄 설명.
